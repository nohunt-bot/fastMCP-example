# 05 驗收測試

這份是給**執行者**看的操作手冊，包含便宜／能力較弱的模型。整份流程設計成不需要
判斷力：每一步都有明確指令、明確的通過條件、失敗時明確的下一步。

## 給執行模型的指示（可直接複製給它）

> 你的任務是驗收 skill-mcp 服務。請照下面的步驟做，**一次只做一步**。
>
> 1. 進入專案目錄，執行 `uv run python acceptance.py`
> 2. 看最後一行：
>    - 出現「全部通過，可以部署。」→ 任務完成，回報「驗收通過，73 項全過」
>    - 出現「有項目失敗」→ 進行第 3 步
>    - 出現「環境還沒準備好」→ 照它印出的「解法」做，然後回到第 1 步
> 3. 找到「第一個要修的是：」那一行，**只處理這一項**，照「下一步：」的指示修改
> 4. 修改後執行 `uv run python acceptance.py --group <該項所屬的組別>`
> 5. 那一組通過後，回到第 1 步重跑全部
>
> **規則：**
> - 一次只修一項，不要同時改多個地方
> - 不要修改 `tests/` 底下的檔案來讓測試通過
> - 同一項連續修 3 次仍失敗就停止，回報「卡在 <項目名稱>，已嘗試 3 次」，
>   並附上原始錯誤訊息
> - 不確定就停下來回報，不要猜

## 執行方式

```bash
# 全部（約 40 秒）
uv run python acceptance.py

# 只跑一組
uv run python acceptance.py --group 安全

# 列出所有組別
uv run python acceptance.py --list

# 只確認服務起得來（最快，約 10 秒）
uv run python acceptance.py --smoke
```

離開碼：`0` 全過、`1` 有失敗、`2` 環境有問題（測試還沒開始）。

## 輸出長什麼樣

通過時：

```
【安全】確認呼叫端（LLM）無法讀取或執行 skill 目錄以外的東西。
────────────────────────────────────────────────────────────
  [通過] 拒絕路徑穿越（../ 與絕對路徑）
  [通過] 拒絕指向外部的 symlink
  ...
```

失敗時：

```
  [失敗] 卡片不含 skill 內文
         為什麼重要：卡片一旦夾帶內文，list_skills 會炸掉 context。
         下一步：檢查 index.py 的 card()，只能有 name/description/tags/scripts。
```

最後一定會有明確結論，不會留下模稜兩可的狀態。

## 各組的意義與優先順序

修的時候照這個順序：

### 1. 安全（最優先）

這組失敗代表**有實際風險**。呼叫端是 LLM，可能被文件內容說服去做不該做的事。
這組在保證：不管模型被怎麼引導，都只能碰到 skill 自己目錄裡的東西。

任何一項失敗都要先修，不要繼續往下。

### 2. 卡住偵測

這組失敗代表 script 卡住時你**查不出原因**——只會看到逾時，不知道卡在哪個端點。
這是最消耗人力的失敗模式。

### 3. 執行政策 / 背景任務

這兩組對應「送出長任務拿 uuid」的流程。失敗代表 uuid 可能遺失，任務跑完卻沒人
能取回結果。

### 4. 輸出預算

失敗代表回傳可能塞爆模型 context。症狀通常是**逾時而不是報錯**，很難查。

### 5. 規格對齊 / 索引 / Hooks / 熱載入 / MCP 介面

功能正確性，重要但不緊急。

## 環境檢查

正式開始前會先確認：

| 檢查 | 失敗時的解法 |
|---|---|
| Python ≥ 3.12 | `uv sync` |
| fastmcp 已安裝 | `uv sync` |
| `skills/` 目錄存在 | 確認在專案根目錄執行 |
| 有 `git` 指令 | 安裝 git（兩項 shell 測試需要） |

環境沒過會直接離開（碼 2），**不會開始測試**——因為環境壞掉時的錯誤訊息很難懂，
先擋下來比較省事。

## 冒煙測試

跑完所有組別後會自動做一次：實際啟動服務、確認 `127.0.0.1:8791/mcp` 有回應、
關閉。

這抓的是單元測試抓不到的問題——例如曾經發生過 CLI 參數漏定義，導致所有測試都
通過但服務根本起不來。

## 直接跑 pytest

驗收程式是 pytest 的包裝。要看原始輸出：

```bash
uv run pytest -q                                    # 全部
uv run pytest -v -k "traversal or symlink"          # 指定
uv run pytest -q --lf                               # 只跑上次失敗的
```

驗收程式提供的額外價值是中文說明、修復指引與明確的優先順序，適合交給不熟悉這個
專案的人或模型執行。

## 新增驗收項目

1. 在 `tests/test_server.py` 寫測試（函式名要能辨識）
2. 在 `acceptance.py` 的 `GROUPS` 對應組別加一個 `Item`：

```python
Item("中文項目名稱", "test_函式名稱",
     "為什麼重要：這項在保護什麼",
     "失敗時該檢查哪個檔案的哪個函式"),
```

`on_fail` 請寫得夠具體——它是弱模型唯一的修復線索。寫「檢查 index.py 的
card()，只能有 name/description/tags/scripts」，不要寫「檢查索引邏輯」。
