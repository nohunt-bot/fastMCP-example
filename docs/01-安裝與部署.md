# 01 安裝與部署

## 安裝

```bash
cd /path/to/skill-mcp
uv sync
uv run pytest -q          # 應該看到 69 passed
```

需要 Python 3.12 以上（`uv sync` 會自動處理）。不需要 Redis、資料庫或任何外部
服務。

## 啟動

### 開發／單機

```bash
uv run skill-mcp --port 8000 --context-tokens 30000
```

### 正式環境（多工作行程）

```bash
uv run uvicorn skill_server.app:app --workers 8 --port 8000 --loop uvloop
```

環境變數（因為工作行程由 uvicorn 產生，不走我們的參數解析）：

```bash
export SKILL_MCP_ROOTS=/srv/skills:/srv/team-skills   # 用 : 分隔
export SKILL_MCP_REFRESH=5
export SKILL_MCP_SCRIPT_CONCURRENCY=8
```

多工作行程可行的前提是服務**無狀態**：每個請求自帶所需資訊，任何工作行程都能
處理，前面放任何負載平衡器都可以，不需要 session affinity。

每個工作行程持有自己的索引（幾百 KB）與自己的更新計時器，所以改動 skill 之後
各行程會在一個更新週期內收斂。

## 一定要設的參數

### `--context-tokens`

**這是最容易設錯、後果最嚴重的一個。**

預設 128000 是給雲端模型的。如果你的地端模型只有 30k context，一定要設：

```bash
--context-tokens 30000
```

為什麼重要：一個很普通的 500 筆內部 API 回應約 59,000 tokens。塞給 30k 的模型
會爆掉，而且**症狀是「逾時」而不是報錯**——時間全花在模型 prefill 一堆它裝不下
的 token。設對之後，同一份回應會被壓成 442 tokens。

搭配 `--context-share`（預設 0.25）決定單次工具結果最多佔 context 的幾成。留
四分之三給系統提示、skill 內文、對話與模型自己的回覆。

### 不需要設定任何可寫路徑

**服務不寫任何檔案。** 沒有狀態目錄、沒有快取檔、沒有日誌檔（日誌走 stdout）。

這代表可以直接搭配 `readOnlyRootFilesystem: true` 執行，不需要 volume，pod 掉
了也沒有東西要救。所有狀態都在你的後端 API 與資料庫。

## 完整參數表

| 參數 | 預設 | 說明 |
|---|---|---|
| `--skills DIR` | `./skills` | skill 根目錄，可重複指定多個 |
| `--host` / `--port` | `127.0.0.1` / `8000` | 綁定位址 |
| `--path` | `/mcp` | 掛載路徑 |
| `--context-tokens N` | `128000` | **客戶端模型的 context 大小** |
| `--context-share F` | `0.25` | 單次結果最多佔 context 幾成 |
| `--hooks-dir DIR` | 無 | 全域 pre/post hook 目錄 |
| `--refresh-interval SEC` | `5` | 索引自動更新間隔，`0` 關閉 |
| `--max-script-concurrency N` | `8` | 同時執行的子行程上限 |
| `--script-timeout SEC` | `30` | 腳本執行上限 |
| `--script-stall-timeout SEC` | `20` | 靜默多久判定卡住，`0` 關閉 |
| `--no-network-env` | 關 | 不轉發 proxy/TLS 環境變數 |
| `--enable-tasks` | 關 | 背景任務模式，需 `uv sync --extra tasks` |
| `--log-level` | `info` | 記錄層級 |

## 公司網路注意事項

服務預設會把這些環境變數轉發給 script：

```
HTTP_PROXY  HTTPS_PROXY  NO_PROXY  ALL_PROXY
SSL_CERT_FILE  SSL_CERT_DIR  REQUESTS_CA_BUNDLE  CURL_CA_BUNDLE  NODE_EXTRA_CA_CERTS
```

**這是刻意的。** 少了 proxy 變數，對外連線不會快速失敗，而是一路 block 到連線
逾時（常常比服務本身的 timeout 還久），症狀看起來就是「script 莫名卡住」。

伺服器環境裡**其他**的變數（例如各種 API 金鑰）不會被繼承——有測試專門驗證這
一點。要傳機密給 script，用工具的 `env` 參數，不要放 `args`（argv 會出現在行程
列表和日誌裡）。

## 效能調校

| 症狀 | 調整 |
|---|---|
| `list_skills` 慢 | 不太可能，這條路徑不碰磁碟。先看 `skill_server_stats()` 的 p95 |
| script 排隊 | 提高 `--max-script-concurrency`（I/O 密集可調高，CPU 密集要調低） |
| 整體吞吐不足 | 改用多工作行程部署 |
| 記憶體成長 | 檢查 `--max-script-concurrency`；每個子行程約 15 MB |

實測（單一工作行程，並行 16）：

| 路徑 | rps | p50 | p95 |
|---|---|---|---|
| `list_skills` | 1,149 | 11.5 ms | 22.3 ms |
| `load_skill` | 1,114 | 11.8 ms | 22.0 ms |
| `run_skill_script` | 181 | 85.8 ms | 97.4 ms |

`run_skill_script` 慢是因為直譯器啟動成本（`python -I` 約 50 ms），這是實體
限制，不是可以調掉的。

多工作行程實測：1 個行程約 1,247 rps，4 個約 1,915 rps——**是 1.5 倍不是 4 倍**，
因為測試用的壓測程式本身也是 Python，先撞到自己的上限。要拿到可靠數字請用非
Python 的壓測工具。

## 健康檢查

```bash
curl -s -X POST http://127.0.0.1:8000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

或直接跑冒煙測試：

```bash
uv run python acceptance.py --smoke
```

服務內建 `skill_server_stats()` 工具，回報索引狀態、子行程計數與各工具的
p50/p95 延遲。
